## The question

A skateboard customer wants a custom deck graphic but can't draw one, and stock artwork is generic.
I wanted to find out whether a model trained and run on consumer hardware could turn a written
description, and optionally a reference image, into usable deck art in a consistent style.

The constraint shaped everything: one laptop GPU with 8 GB of VRAM, no cloud inference and no
third-party image API.

## What I built

- **Three style adapters.** LoRA adapters for `ukiyo-e`, `minimal-geometric` and `retro-poster`,
  trained on Stable Diffusion 1.5 using a 148-image dataset. Every image is public domain, CC0 or my
  own work, and its licence is recorded in the manifest.
- **A generation service.** FastAPI with one resident pipeline, upload validation for reference
  images, a single-flight lock and live progress telemetry during denoising.
- **A frontend with a 3D preview.** React, TypeScript and Three.js. You write a prompt, pick a style,
  optionally add a reference and watch the progress, and the result lands on a 3D deck you can
  rotate. You can also map your own artwork onto the deck without generating anything.

I built it as a ladder of six prototypes: the 3D deck viewer first, then a base-model benchmark,
reference conditioning, a LoRA smoke test, style learning and finally the integrated app.

## How it works

Prompt, style, an optional reference image, live denoising progress, the result on the deck, and a
download of the PNG plus a JSON metadata sidecar. The first request loads the pipeline, which takes
about 30 seconds. After that, a generation takes 12–13 seconds.

## How I tested it

528 pytest, 183 Vitest and 38 Playwright tests run in GitHub Actions on Windows, the platform the
project was validated on. The browser tests drive a real WebGL context against a mocked API.

No test loads the model. A green build shows that the code, the API contracts and the interface
work. It says nothing about image quality. Real generations are evidenced separately, in the
experiment registry and the GPU validation runs. I also ran the project from a clean clone, which
surfaced five defects that a warm machine had hidden.
